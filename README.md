# yanll

yanll restructures NonLinLoc (NLL) into a containerized JSON-in / JSON-out locator: one
image, `ingv/yanll` on Docker Hub, with NLL built from source at a pinned commit and a
thin command-line adapter, that a site configures at run time with its own NLL
control-file templates and station catalog. yanll owns the JSON documents and the life
cycle of the grids; everything about velocity models, projections, search parameters and
stations stays in NLL's own language, in a directory the site mounts. The contract is
`docs/configuration.md`.

INGV is the first user: its configuration is `config/ingv/`, generated from the
production host `nll.int.ingv.it`, and the project's acceptance test is that, with it
mounted, the container writes production's control files byte for byte and reproduces
production's locations for 21 recent events in 1D and 3D. The production automation
itself (event polling, MySQL, web page) is not replicated; `docs/production-flow.md`
describes it, since that is where NLL's configuration was learned.

Phases 1 to 3 (release 1.0.0) built the image with the INGV inputs inside it; phase 4
(release 2.0.0) moved them into `config/ingv/`, added the configuration contract with a
synthetic example (`config/example/`) and the Docker Hub publication.

## Layout

| Path | Content |
|---|---|
| `docs/configuration.md` | the configuration contract: what a site creates and where, placeholders, station catalog, data directory, how to add a model or a station and invalidate grids |
| `docs/json-schema.md` | input and output documents of `yanll-locate` |
| `docs/production-flow.md` | how a location is computed on the INGV production host: inputs, control files, outputs, how to reproduce one by hand |
| `docs/comparison-report.md` | the container's locations against production for the fixture events, written by `tests/yanll-compare` |
| `docs/comparison-table.md`, `docs/comparison-table.json`, `docs/comparison-viz.html` | the same comparison location by location, as a table, as data and as a self-contained page |
| `config/example/` | a synthetic 1D configuration with six stations and one event made with Time2EQ: the smallest thing that proves the contract (`config/example/README.md`) |
| `config/ingv/` | the INGV configuration: station catalog and 18 models, generated by `scripts/generate-ingv-config.py` from `reference/` (`config/ingv/README.md`) |
| `reference/production/` | read-only copies of the production scripts, models, corrections, control files and NLL 7.00.00 sources, paths mirrored, secrets removed (`reference/production/README.md`) |
| `fixtures/events/` | 21 recent production runs (observations, 1D and 3D `.hyp`, the same observations as `input-{1d,3d}.json`) used as oracles (`fixtures/events/README.md`) |
| `Dockerfile`, `compose.yaml` | the image: NLL at a pinned commit plus `bin/`, nothing of a site; the compose file mounts the configuration, the data directory and what the checks need |
| `bin/` | the scripts in the image: `yanll-locate` (JSON in, JSON out), `yanll-obs2json` (observation file to input JSON), `yanll-make-grids` (model and travel-time grids) |
| `tests/` | JSON I/O tests and `yanll-compare`, run in the container from a mount, not in the image |
| `scripts/` | host-side and check scripts: reference check, INGV generator, station snapshot refresh, example event synthesis and check |
| `CHANGELOG.md` | one line per change, by release |

There is no Makefile on purpose: every build, run and check is a direct `docker`
command (or the shell script it names), as listed below.

## The image

```
docker pull ingv/yanll:latest        # last release (from the first vX.Y.Z tag); also :X.Y.Z and :develop
docker compose build                 # the same image from this checkout, as yanll:latest
```

The build clones https://github.com/ut-beg-texnet/NonLinLoc at the commit pinned in the
`Dockerfile` (`NLL_COMMIT`), compiles it with CMake on `debian:bookworm-slim` and copies
`NLLoc`, `Vel2Grid`, `Grid2Time`, `GridCascadingDecimate` and `Time2EQ` into the runtime
image with `bin/`. The image is about 120 MB, `linux/amd64` only: the compose file pins
the platform, so on an Apple Silicon host it builds and runs under emulation (NLLoc
compiled for arm64 never terminates). Its OCI labels record the yanll revision and the
NLL commit it was built from (NLL is GPL-3). Bump the commit on purpose, in its own
commit, and rerun the comparison: that is the only way to see what a bump changes.

Inside the image: `YANLL_CONFIG=/config` is where the configuration is mounted,
read-only; `YANLL_DATA=/data` is the writable directory for grids and work files. A
container without a configuration mounted does nothing: `yanll-locate` and
`yanll-make-grids` stop with exit code 2 and a message that names the missing file and
`docs/configuration.md` (`yanll-obs2json` only converts a file and reads no
configuration).

## Configuring a site

A configuration is one directory: a station catalog in FDSN station text and, per
model, NLL control-file templates whose few `@NAME@` placeholders yanll fills (the
observation file, the grid roots, the corrections `INCLUDE`, the station `GTSRCE`
line). The contract, with every placeholder and what yanll expects of each template, is
`docs/configuration.md`. With `compose.yaml`, the host directory to mount is chosen by
the `YANLL_CONFIG` variable on the command line (`config/ingv` when unset), the data
directory by `YANLL_DATA` (`./data`), the container's user by `YANLL_USER` (root). The
shortest way to see it work is the example.

### One location end to end, on the example

`config/example/` is a site with six fictional stations around 45.0 N 10.0 E, one
flat-layered velocity model called `synthetic`, zero station corrections, and one event
whose arrival times were computed by Time2EQ from a known hypocenter: latitude 45.05,
longitude 10.08, depth 8.0 km, origin time 2026-01-01T00:00:00Z. Locating it:

```
YANLL_CONFIG=./config/example docker compose run --rm -T yanll yanll-locate /config/event/event.json > out.json
```

or, without this checkout, with the published image and two mounts (the configuration
read-only, the data directory writable by the user the container runs as; without
`--user` it runs as root and the grids come out root-owned):

```
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/config/example:/config:ro" -v "$PWD/data:/data" ingv/yanll:latest yanll-locate /config/event/event.json
```

The first run builds the model grid (Vel2Grid) and twelve travel-time grids (Grid2Time)
in seconds; the output document carries `origin.latitude`, `origin.longitude`,
`origin.depth` and `origin.time` within a few hundred metres and hundredths of a second
of the hypocenter above, twelve phases used, and the rendered control file in
`nll.control_file`. The scripted form of this check, with the project tolerance (1 km in
epicentre, 2 km in depth, 0.5 s), is

```
YANLL_CONFIG=./config/example docker compose run --rm yanll /scripts/check-example.sh
```

and `scripts/make-example-event.sh` regenerates `config/example/event/event.json` from
`config/example/event/time2eq.in`. A new site starts by copying `config/example/`,
replacing the catalog and the velocity model, and adjusting the grids and the search in
the three templates.

### The INGV configuration

`config/ingv/` has the catalog `stations.txt` (a snapshot of the INGV `fdsnws-station`
service, refreshed by `scripts/fetch-stations.sh`) and `models/`: the 17 regional 1D
models named by zone (`Alpi-Occidentali_1`, ..., `Sardegna_12`) and the 3D model
`TOMORAMA-2013`, written by `scripts/generate-ingv-config.py` from the production
scripts and files under `reference/production/`. Nothing in it is typed by hand: the
generator puts every production fact (the zone origins, the `LOCGRID` arithmetic, the
signature lines, the decimation steps) literally into the templates, and the tests
below prove the rendered control files are production's. Rerun it after a change under
`reference/` and commit. The 3D model body (1.2 GB) is not in the repository: copy the
production pair `TOMORAMA_zmax800_deep.{P,S}.mod.{hdr,buf}` to
`${YANLL_DATA}/model/TOMORAMA-2013/model.{P,S}.mod.{hdr,buf}` (checksums in
`docs/production-flow.md`, section 2.2); without it only the 1D models locate.

`compose.yaml` mounts `config/ingv/` by default, so every command below runs with the
INGV configuration unless `YANLL_CONFIG` names another directory.

## The data directory

Grids are large and derived, so they live outside the image and the configuration, in
the directory `YANLL_DATA` names (`./data` by default, mounted at `/data`). The
container writes there as root unless `YANLL_USER=uid:gid` is set (the directory must
then be writable by that user). On an NFS export with root squash, as `/mnt/nll` on
`nll-dev`, root in the container cannot write at all: set `YANLL_USER` to a user that
can (`YANLL_DATA=/mnt/nll/yanll YANLL_USER=1000:1000` there).

```
model/<name>/model.{P,S}.mod.{hdr,buf}       model grid: Vel2Grid output (110 MB per INGV zone), or put there by the site (TOMORAMA-2013)
time/<name>/time.{P,S}.<STA>.time.{hdr,buf}  travel-time grids: INGV 1D 55 MB and about 1.5 s each, 3D cascading 22 MB and about 1 min per station
time/<name>/tmp/                             runs in progress
locate/<run>/                                work directory of a location, removed on success unless --keep
compare/<run>/<dim>/                         work directories of tests/yanll-compare
```

A grid is generated only when it is missing, so a changed station or model is
invalidated by deleting files: `docs/configuration.md` lists what to delete for each
case.

## Generating grids

```
docker compose run --rm yanll yanll-make-grids <model> <station>...
```

Writes the model grid if missing (when the model has a `vel2grid.in`) and a travel-time
grid for every listed station that has none yet, one Grid2Time run per station and
phase from the model's `grid2time.in`, decimated afterwards when the model has a
`cascade` file. Station coordinates come from the catalog; a code listed twice takes
its first line, a code missing from the catalog, or a station outside the model, is
reported and skipped and its phases get weight 0 in the location. `yanll-locate` calls
this for the stations of each input, so it is needed by hand only to prepare grids in
advance: the full INGV set (17 zones with about 800 stations each, 1100 stations in 3D)
would take about 1.5 TB and days of CPU.

## Locating one event

```
docker compose run --rm -T yanll yanll-locate /fixtures/events/47442632_147825511/input-1d.json > out.json
docker compose run --rm -T yanll yanll-locate - < input.json > out.json
```

The input names the model (a directory of the mounted configuration), whether to apply
the model's station corrections, and the arrivals; the output carries the
maximum-likelihood hypocentre, the expectation, the quality and uncertainty blocks of
the `.hyp`, one entry per phase and the control file that was run. Both documents are
described in `docs/json-schema.md`. The grids the stations need are generated on the
fly; the work directory under `locate/` is removed unless `--keep` is given or the run
fails. An `NLLOC_OBS` observation file becomes an input document with
`yanll-obs2json --model <model> <file>`.

## Comparing with production

```
docker compose run --rm yanll /tests/yanll-compare            # all fixture events, writes docs/comparison-report.md
docker compose run --rm yanll /tests/yanll-compare --dims 1d --report /data/compare/one.md 47442632_147825511
```

For every run under `fixtures/events/` the production control file is reused with its
paths rewritten, the grids are generated for the stations of the observation file (3D:
for the stations that had a grid in production, so that both locations see the same
phases), NLLoc runs, and the maximum-likelihood hypocentres are compared: 1 km in
epicentre, 2 km in depth, 0.5 s in origin time. `--all-stations` adds an informative 3D
row per event (`3d-all`) with grids for every station: production has had no 3D grid
for stations added since June 2023 (`docs/production-flow.md` section 6), so those rows
show what the missing grids cost. The report lists, per event and dimension, both
locations, the differences, the number of phases used and the largest offset between
the station coordinates of the two runs.

## Checking

```
scripts/check-reference.sh
docker compose run --rm yanll python3 -m unittest discover -s /tests -v
YANLL_CONFIG=./config/example docker compose run --rm yanll /scripts/check-example.sh
docker compose run --rm yanll /tests/yanll-compare
```

In order: the phase-1 check (every script and file named in `docs/production-flow.md`
exists under `reference/production/` or `fixtures/`, no copied file holds a
credential); the JSON I/O tests with the INGV configuration (the observation file and
the control file rendered from the fixture inputs are the production ones byte for
byte, paths aside, for all 21 events in 1D and 3D; the committed input documents are
what `yanll-obs2json` writes; one 1D location reproduces production within tolerance;
malformed inputs are rejected; a missing configuration is refused with a message naming
the documentation); the example located end to end against its known hypocenter; and
the comparison with production (hours of grid generation the first time, minutes once
the grids exist), whose report is committed as `docs/comparison-report.md`. The tests
need the image, the data directory and, the first time, a few minutes of grid
generation for one zone.

To see that the image holds nothing of a site: `docker run --rm yanll:latest ls /opt/yanll`
lists `bin` only, and `yanll-locate` or `yanll-make-grids` run without a configuration
mounted exit with code 2 naming `docs/configuration.md`.

## CI and Docker Hub

GitLab CI (`.gitlab-ci.yml`) runs on every push: the reference check, the JSON I/O tests
and the example check, each in a freshly built image. On `develop` the pipeline then
publishes the image as `ingv/yanll:develop`; on a tag `vX.Y.Z` as `ingv/yanll:X.Y.Z` and
`ingv/yanll:latest`; other branches build and test only. The publish job rebuilds the
image with the OCI labels set from the pipeline (`org.opencontainers.image.revision`,
`.version`, `.source`, plus the NLL repository and commit) and logs in to Docker Hub
with the project CI variables `DOCKER_HUB_USERNAME` and `DOCKER_HUB_ACCESS_TOKEN`. The
comparison with production is a manual job of the same pipeline, meaningful only on a
runner that has the 3D model body and the grids (the shared runners have neither).
